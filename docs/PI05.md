# PI0.5 LoRA baseline

Fine-tune an OpenPI/JAX PI0.5 policy on episode-labelled LeRobot data and evaluate
it in ManiSkill with asynchronous absolute-joint actions. The layout follows the
GR00T baseline: one entry point, one config, one algorithm module and focused
helpers in `utils/pi05_utils`.

This is the repository's PI0.5 baseline, replacing the legacy LeRobot
full-parameter SFT/Flow-SDE GRPO implementation. The old
`train/train_pi05_sft.py`, `train/train_pi05_grpo.py` and `train/eval_pi05.py`
commands have been removed. Use the commands below instead; legacy Torch
checkpoints and `final_policy/` packages cannot be resumed or evaluated here.
Existing datasets still need the named joint/RGB and instruction checks below;
a legacy dataset is not automatically a compatible data contract.

| Path | Purpose |
| --- | --- |
| `train/train_pi05.py` | Fine-tune by default; evaluate with `--evaluate`. |
| `train/train_configs/pi05_config.py` | Shared CLI arguments and baseline settings. |
| `algo/pi05.py` | OpenPI model, masked flow loss, weight loading and inference. |
| `utils/pi05_utils/data.py` | Named joint/RGB adapters, normalization and dataset preparation. |
| `utils/pi05_utils/training.py` | Sampling, optimizer updates and the training loop. |
| `utils/pi05_utils/checkpoint.py` | Run identity, resumable checkpoints and evaluation results. |
| `utils/pi05_utils/runtime.py` | Async action queue and private inference worker. |
| `utils/pi05_utils/eval.py` | Native scene creation and standard/background Eval50. |

## Install

Use Python 3.11 for the pinned OpenPI package. Model code comes from DexJoCo
`8d23b0fab23b17a58c4b55f3942e17013aaf8267` (JAX 0.5.3, Flax 0.10.2,
Orbax Checkpoint 0.11.13). From the DexArena repository root:

```bash
git clone https://github.com/brave-eai/dexjoco.git /path/to/dexjoco
git -C /path/to/dexjoco checkout 8d23b0fab23b17a58c4b55f3942e17013aaf8267
uv venv --python 3.11 /path/to/pi05-venv
uv pip install --python /path/to/pi05-venv/bin/python \
  --override <(printf 'numpy==2.2.6\n') \
  -e /path/to/dexjoco/openpi -e /path/to/dexjoco/openpi/packages/openpi-client
uv pip install --python /path/to/pi05-venv/bin/python --no-deps lerobot==0.4.4
```

The NumPy override reconciles the pinned OpenPI package and its client metadata.
Run evaluation from the existing ManiSkill environment and select the model
interpreter with `--policy-python`. Both environments need access to this
checkout; the parent starts the worker over private stdio pipes. If one
interpreter already contains both dependency stacks, it can serve both roles.
Allocate one visible model GPU before launch. Job scheduling and filesystem
capacity management belong to the deployment environment.

## Prepare data

Training consumes the episode labels already stored in the dataset and checks
those labels against `utils.dex_tasks.dataset_episode_instruction`. Evaluation
selects the instruction with `utils.dex_tasks.episode_instruction(env_id, seed)`.
See [the shared instruction protocol](DEX_TASK_INSTRUCTIONS.md).

Provide the robot/controller binding recorded for the dataset. It contains
`status: LIVE_ROBOT_CONTROLLER_BINDING_PASS`, `uid`, `tasks`, ordered
`qpos_joint_names` and `action_joint_names`, and `groups` with `joint_names` and
`controller` class names. These names must describe the source recording order.
The live evaluation robot is checked against the same binding after resets.
`utils.pi05_utils.binding` writes the binding from the registered task
environment, the robot and controller the released demonstrations were
recorded with:

```bash
python -m utils.pi05_utils.binding --env-id OfficeDeskClickMouse-Sharpa-v1 \
  --output /path/to/clickmouse-binding.json
```

```bash
python -m utils.pi05_utils.data \
  --dataset-root /path/to/clickmouse_rig_vla_v3.0 \
  --binding /path/to/clickmouse-binding.json \
  --env-id OfficeDeskClickMouse-Sharpa-v1 \
  --output /path/to/clickmouse-data.json
```

The output holds camera shapes, channel names, shard hashes and per-dataset
normalization statistics. Exact quantiles use the complete task's state/action
arrays in CPU memory. State is measured joint position; action is an absolute
`pd_joint_pos` target in radians. Normalization precedes model padding, and
padded timesteps/channels are masked in the flow loss.

## Fine-tune

```bash
/path/to/pi05-venv/bin/python train/train_pi05.py \
  --dataset-path /path/to/clickmouse_rig_vla_v3.0 \
  --data-contract /path/to/clickmouse-data.json \
  --binding /path/to/clickmouse-binding.json \
  --base-model-path /path/to/pi05_base \
  --base-manifest /path/to/pi05_base-manifest.json \
  --output-dir /path/to/runs/clickmouse-lora
```

The base directory contains `params/`; its manifest lists `{name, bytes, sha256}`
for each parameter file relative to that directory. The original
`checkpoints/pi05_base/` prefix is also supported. Create the output parent first.
`utils.pi05_utils.base_manifest` writes that manifest from a downloaded Base
(the original lives at `gs://openpi-assets/checkpoints/pi05_base`, readable
anonymously over HTTPS):

```bash
python -m utils.pi05_utils.base_manifest --base /path/to/pi05_base \
  --output /path/to/pi05_base-manifest.json
```

| Setting | Value |
| --- | --- |
| Starting weights | Original PI0.5 pretrained checkpoint |
| Backbone / expert | `gemma_2b_lora` / `gemma_300m_lora` |
| LoRA rank / alpha | 16 / 16 for backbone; 32 / 32 for expert |
| Single arm | 29 physical channels, model capacity 32, 30,000 updates |
| Dual arm | 58 physical/model channels, 60,000 updates |
| Global batch / action horizon | 32 / 30 |
| Optimizer | AdamW, gradient clip 1, no EMA |
| LR schedule | 5e-5 peak; 10,000 warmup; 1,000,000 decay steps; 5e-5 end |
| Checkpoints | Every 10,000 updates and at the final update |

Use `--accumulation-steps 2` for microbatch 16 with global batch 32. The model's
freeze filter also determines trainable non-LoRA leaves; each run records the
full parameter inventory. Repeat the same command with `--resume` to restore
model parameters, optimizer state, update count and RNG from the latest complete
checkpoint. Run metadata binds the dataset, normalization, code and instruction
protocol. An output lock prevents concurrent writers to the same run.

## Evaluate

```bash
python train/train_pi05.py --evaluate \
  --model-path /path/to/runs/clickmouse-lora \
  --output-dir /path/to/eval/clickmouse-standard \
  --policy-python /path/to/pi05-venv/bin/python
```

Add `--scene-background s1`, `s2` or `s6` and use a distinct output directory for
each background. Evaluation uses the existing shared scene factory, fixed
256x256 camera profile, native robot, controller and episode horizon. Install
the native task and background assets before launching.

The controller requests a new chunk when fewer than 24 actions remain, aligns
predictions by observation control step, drops expired prefixes and linearly
blends overlapping targets. Physics and episode time continue while inference
runs. A reset invalidates old responses and refreshes the live robot binding.

Evaluation uses seeds 10001-10050. `episodes/` retains attempts and completed
seeds; infrastructure errors remain unscored. Repeat with `--resume` to continue
pending seeds under the same identity. A final success rate is reported only
when all 50 seeds complete. Long-horizon policy composition is a follow-up.

## Published inference-only checkpoints (Base + trainable overlay)

The compact `pi05_trainable_npz_v1` format contains **all trainable arrays**, not
only LoRA matrices. Non-LoRA vision/action/time parameters selected by the
model's freeze filter must also be retained. Frozen pretrained weights are
reused from the original `gs://openpi-assets/checkpoints/pi05_base` checkpoint.
No optimizer or RNG state is included: this is not a training-resume format.
The existing full-run `--evaluate` and `--resume` admission checks are unchanged.

Download one task package from `SIPAIR/DexArena` at an immutable commit revision
(the contribution PR is not necessarily merged). Obtain the original Base once
and retain its complete `params/` directory. Do not use a different fine-tuned
checkpoint as the Base. The package embeds exact Base file sizes and SHA256s.

```text
ckpt/pi05/<official-task-env-id>/
  ckpt/trainable.npz
  config.json
  manifest.json
  load_pi05.py
```

Use the repository loader below, not the downloaded Python script. The loader
checks the reconstruction certificate/file hashes, pinned OpenPI source, final
update count, normalization, all Base files and the exact model parameter tree.
It overlays trainable arrays without adding LoRA twice, casts frozen Base arrays
to the saved dtype (BF16), then checks every array's shape, dtype, finite values
and SHA256. It does not silently discard missing or unexpected parameters.

```python
import jax
from algo.pi05 import load_compact_model, NativeJointInference
from utils.pi05_utils.data import camera_mapping

model, prepared, certificate = load_compact_model(
    "/path/to/NutBoltPickBolt-Sharpa-v1",
    "/path/to/pi05_base",  # contains params/
    device=jax.devices("gpu")[0],  # use your allocated device
)
infer = NativeJointInference(
    model, prepared,
    live_state_names=prepared["state_names"],
    camera_keys=camera_mapping(prepared),
)
```

The evaluation entry point accepts a package directly. It needs the Base
directory and a controller binding written from the registered environment
(the binding's `--task` must include the package's own task name, `task` in
its `config.json`). The packages were trained under the tasks' earlier
environment ids, so pass the current `<Task>-<Hand>-v1` id with `--env-id`;
the package's `config.json` keeps the trained id. The policy worker overlays
the package's trainable arrays on the pinned Base, and the Eval50 protocol
(seeds 10001-10050, resumable, infrastructure errors unscored) is the same as
for a training run:

```bash
ENV=CabinetPouringOpenCabinet-Sharpa-v1
python -m utils.pi05_utils.binding --env-id $ENV --task dooropen \
  --output /path/to/opencabinet-binding.json
python train/train_pi05.py --evaluate \
  --model-path /path/to/ckpt/pi05/CabinetPourDoorOpen-v1 \
  --base-model-path /path/to/pi05_base \
  --binding /path/to/opencabinet-binding.json --env-id $ENV \
  --output-dir /path/to/eval/opencabinet-package \
  --policy-python /path/to/pi05-venv/bin/python
```

The programmatic entry point above remains for custom controllers. Neither
path bypasses the live robot/camera/controller admission: call `infer`
through the observation-step-aligned async controller with the official task
prompt and live state order; the ready certificate alone does not certify an
environment.

Long packages live under `ckpt/pi05/long-horizon/<official-long-env-id>/`.
Their root `config.json` describes ordered independent stage policies, with
`reset_between_stages: false`. Each `stages[].package` is a relative compact
package directory loadable by the same function; use its own config/statistics.
These are not merged long-horizon models. Full long-environment switching is
outside this loader PR. No Base weights are duplicated per task or stage.

## Regression tests

The CPU checks do not load pretrained weights or require JAX, OpenPI, ManiSkill
or a GPU. With NumPy, pytest and tyro installed, run from the repository root:

```bash
python -m pytest tests/test_pi05.py tests/test_pi05_compact.py tests/test_dex_task_instructions.py -q
```

They cover CLI dispatch, named joint dimensions, the shared instruction table,
asynchronous observation-step alignment and reset invalidation, live robot
rebinding, private transport, Eval50 accounting and removal of legacy imports.
These checks are not substitutes for model restoration or native GPU evaluation.
